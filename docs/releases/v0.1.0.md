# VX Bridge 0.1.0

VX Bridge forwards shot data from ProTee Labs to Infinite Tees or GSPro OpenAPI
on the same Windows PC. This is the first public release.

## What this release provides

- A Windows x64 application with an icon near the clock. Labs continues to
  manage the launch monitor; the game calculates ball flight.
- A remembered choice of Infinite Tees, GSPro OpenAPI or Standby. Only the
  selected game receives shots. There is no automatic game selection or failover.
- Connection status, shot-delivery counts and local logs. Logs omit shot
  measurements and device/player identifiers; nothing is uploaded automatically.
- Guarded shutdown: Quit waits for Labs to disconnect. A game connection failure
  does not deliberately close the Labs connection. Missed shots are not replayed.
- Per-user Setup, repair and uninstall, with optional launch at Windows sign-in.
  Ordinary application startup does not run Windows Installer or attempt repair.

These are implemented capabilities, not a claim of live-equipment qualification.
Read [Limits](#limits) before installing.

## Requirements

Use Windows x64, an activated ProTee VX with ProTee Labs already working, and a
licensed Infinite Tees or GSPro installation on the same PC. For GSPro, use its
public **OpenAPI / APIv1 Connect** application, not the native VX receiver.
VX Bridge does not supply a game or replace an existing license.

## Installation

1. Download the [v0.1.0 installer ZIP](https://github.com/devigned/vx-bridge/releases/download/v0.1.0/vx-bridge-installer-windows-amd64-v0.1.0-5401cf26d19238b04ba3dbb8ecfa60442616ca79.zip).
   Do not select the application-only ZIP, separate MSI or **Source code**.
2. In ProTee Labs, select **Game Options > Disconnect**. Close any existing
   receiver through its own controls. Do not run two receivers or replace the
   vendor's `GSPconnect.exe`.
3. Right-click the ZIP and select **Extract All**. Open the extracted folder.
   Keep all nine files together, including `setup.exe` and `bridge.msi`.
   Do not run Setup from inside the ZIP or mix files from different builds.
4. Open `setup.exe` as the Windows user who will use the bridge, not as
   administrator. Select **Install**. Do not double-click `bridge.msi`.
5. Leave **Auto-launch on Windows Startup** off unless the bridge should open
   when you sign in. It is off on a fresh install.
6. Wait for Setup to report success. At **Start the bridge now?**, select
   **Start bridge** to open it once, or **Not now** to open **VX Bridge** from
   Start later. Starting it once does not enable auto-launch.

If Windows blocks Setup, stop and
[report the warning](https://github.com/devigned/vx-bridge/issues).
Do not disable security protections or bypass the warning.

## First use

1. Open the game and enter a playable practice scene. For GSPro, also open
   **OpenAPI / APIv1 Connect**.
2. Open **VX Bridge** from Start if it is not running. Find its icon near the
   Windows clock; check the hidden-icons arrow if necessary.
3. Right-click the icon. Select **Use Infinite Tees** or **Use GSPro OpenAPI**.
   A checkmark shows the applied choice. The bridge remembers it for next time.
4. Use ProTee Labs' normal Connect action if needed. The bridge does not open
   Labs or the game, or connect Labs for you.
5. Check the bridge menu. Labs should be connected and the selected game should
   show **Connected (transport only)**. Then check the game itself before
   swinging. A data connection does not establish that the game is ready.

Wait for each shot's visible result before the next swing. To change games,
stop swinging, let the result finish, select the other game and wait for
switching to finish. **Standby (discard shots)** sends to neither game.

To finish, select **Game Options > Disconnect** in ProTee Labs, then **Quit** in
VX Bridge. Do not force the bridge closed while Labs is attached.

For repair, recovery or connection problems, see the
[installation guide](https://github.com/devigned/vx-bridge/blob/main/docs/INSTALL.md)
and [FAQ](https://github.com/devigned/vx-bridge/blob/main/docs/FAQ.md).

## Limits

The release passed automated build and static file checks. Interactive
installation, Windows sign-in, installer servicing and live Labs/game use,
including GSPro and game switching, remain unqualified for these binaries.
Earlier installer and equipment observations used different builds and do not
qualify v0.1.0.

The Windows programs and installer are not publisher-signed (Authenticode).
The signed Git source and tag do not sign those files. Checksums detect changed
or damaged bytes; they do not authenticate a publisher.

Missed shots are lost, not saved for later. If delivery is uncertain, check the
game before swinging again: it may have received the shot. A failed upgrade is
not guaranteed to restore the previous version; keep the bridge stopped until
Setup verifies recovery.
